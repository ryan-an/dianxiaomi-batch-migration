# 德国站标题、描述与 Bullet Point

版本：v0.4.25。规则依据用户确认、截图及右侧内置浏览器的页面DOM和实际手动操作。

## 箱子数量

- 用户确认：箱子数量为必填时固定填1。德国Anzahl von Paketen(箱子数量)与其他站点相同属性均使用此规则。
- 仅定位form_item_number_of_boxes.0.value或data-path="number_of_boxes.0.value"的输入框，不使用泛化的“数量”文字匹配。库存、Number of Items和Item Package Quantity沿用各自规则。
- 支持标签必填星号、aria-required和原生required。非必填保持原值，字段不存在跳过并记录。
- 必填时覆盖已有值为1，写入触发表单事件并重新定位回读；重绘丢值最多重试3次，禁用/只读或拒绝保留值时记录具体错误。
- 正常填写阶段处理，提交前再次检查并补齐；检查及补填结果写入日志。
- 现场证据：docs/evidence/required-box-count.json；离线回归：tests/box-count-browser.cjs。本轮现场仅采集DOM，未修改或发布商品。

## 德文下拉选项

- 必填物品状况精确匹配New(新的)或Neu(新的)，均表示“新的”；不使用包含new/neu的模糊匹配，不选择Gebraucht - Wie neu、Sammlerstück - wie neu、Neu - OEM或Neu - Geöffnete Verpackung。
- 不需要电池精确匹配No(不)或Nein(不)，当前已选Nein时直接确认，不重新展开并等待英文No。
- 等价规则只传给这两个字段，其他下拉与单位规则沿用现有逻辑。多个等价候选同时出现时仍报歧义，不猜选。
- 填写日志记录物品状况实际显示文本。提交前再次检查并补齐必填物品状况；字段非必填或不存在仍跳过。
- 现场故障：10:42:53开始选择物品状况，10:43:13超时；当时代码写死New(新的)，真实选项是Neu(新的)。电池同样因已选Nein而仍等待No超时。实际商品184807703388766909已手动选中Neu验证，未保存或发布。
- 证据：docs/evidence/german-condition-options.json；回归：tests/german-condition-browser.cjs，使用捕获的完整德国选项进行离线填写与提交前补填测试，包含英文、已选值、非必填/缺失字段、歧义与排除其他状况。

## 新品图片

- 仅“德国/DE”且同一行“新品”为“是”时执行。表格原始列保存在record.data中，空白或“否”均不触发；英国即使标“是”也不触发。
- 字段填写后、发布前，按当前顺序保留第一张主图，逐张删除后续附图，每步回读数量并确认主图地址不变。
- 先悬浮主图a.icon-operate：对按钮及父容器触发mouseover（冒泡）和mouseenter（不冒泡），等待菜单可见后，再点击title="小秘美图"的菜单项进入新标签。此菜单依赖悬浮，单独click不会展开。后台只接管本次新开、来自当前商品的编辑器，不控制已存在的同地址标签。
- 编辑器外层为/web/newImageEditor，实际操作界面为/api/meituv2/editor.htm的iframe。专用内容脚本仅匹配该iframe，all_frames=true，沿用现有店小秘域名权限。
- 点击“.crop_module .open”（裁剪/旋转），按W/H后缀定位两个输入框，写入300、300并触发表单更新，核对后点击“应用”。不点击旋转或翻转。
- 右上角button.save展开保存菜单，精确选择“保存并应用”。兼容随后出现的.save_box内“保存”按钮；不选择保存至图片空间或本地。
- 现场版本在“保存并应用”后立即保存并自动关闭编辑标签。即使消息响应随关闭而中断，也不会重复点击保存；持续核对原商品表单的一张300×300主图和新图片地址，确认后才继续。
- 当前表单已是一张300×300图片时直接核对通过，避免断点继续反复裁剪。提交发布前再次检查数量与尺寸。图片操作失败、编辑器歧义或应用结果未确认时，本条记失败并保留页面，继续下一条；原有普通字段警告后仍发布的规则不变。

## 站点与输入

- DE、de、全角 DE 与“德国”双向等价。店铺仍按上传表的店铺名称匹配，不把店铺名称中的 DE 当作站点。
- 已验证“移德国.xls”的两条有效产品，店铺均为万万欣DE，翻译分别为“4 Stück Edelstahl Gewürzschalen”和“3 Stück Aufbewahrungskorb”。
- 德国行忽略“产品数量”字段，不校验或替换标题数量；“德国标题翻译”不能为空，缺失时该行记为数据错误。
- 德国价目表货币字段存在时使用 EUR(欧元)，英国继续使用 GBP(英镑)。其他填写与发布流程沿用现有逻辑。

## 编辑与下载

1. 采集后保留原始标题用于对应链接和产品定位。
2. 编辑时将整个产品标题替换为本行“德国标题翻译”，不套用英国的首个数量替换规则。
3. 将产品描述完整替换为同一个德文标题。文本按纯文本转义为 HTML，避免把表格中的尖括号等内容当作可执行标记。
4. 第一条 Bullet Point 写入同一个德文标题；扫描全部现有 Bullet Point，将其余条目全部清空。
5. 标题、描述和 Bullet Point 均回读核对；描述和 Bullet Point 在提交前再次检查及补齐。字段在重绘后重新查找，写入未保留时重试。
6. 下载结果仍为用户确认的 8 列，最终标题使用页面实际写入的德文标题。

## 字段定位与编辑器同步

- 产品描述：按用户提供的 data-path="product_description.0.value" 定位区域，再读取其中 textarea 的动态 ID，未写死 ckeditor14。
- 描述区域的 CKEditor 是 iframe 富文本编辑器，不能仅依赖隐藏 textarea 的显示值来确认最终内容。
- 使用独立 MAIN 世界脚本调用 CKEditor 公开 setData / getData / updateElement 接口，写入后触发 change 和表单事件，分别检查编辑器内容与隐藏表单值。
- 扩展隔离脚本与页面脚本通过只支持读写产品描述的固定消息通信；不增加浏览器权限，不访问私有框架状态、Cookie 或账号凭据。
- Bullet Point：按 textarea[id^="form_item_bulletPoints_"] 扫描，并按数字索引排序。
- 定位信息证据见 docs/evidence/german-content-fields.json。当前页面未通过浏览器工具直接读取，结构由用户粘贴提供；编辑器脚本使用店小秘公开的 4.6.2 版本。
