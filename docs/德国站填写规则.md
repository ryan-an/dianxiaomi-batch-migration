# 德国站标题、描述与 Bullet Point

版本：v0.4.21。规则依据用户确认及当前编辑页粘贴的真实 DOM。

## 站点与输入

- DE、de、全角 DE 与“德国”双向等价。店铺仍按上传表的店铺名称匹配，不把店铺名称中的 DE 当作站点。
- 已验证“移德国.xls”的两条有效产品，店铺均为万万欣DE，翻译分别为“4 Stück Edelstahl Gewürzschalen”和“3 Stück Aufbewahrungskorb”。
- 德国行忽略“产品数量”字段，不校验或替换标题数量；“德国标题翻译”不能为空，缺失时该行记为数据错误。
- 德国价目表货币字段存在时使用 EUR(欧元)，英国继续使用 GBP(英镑)。其他填写与发布流程沿用现有逻辑。

## 编辑与下载

1. 采集后保留原始标题用于对应链接和产品定位。
2. 编辑时将整个产品标题替换为本行“德国标题翻译”，不套用英国的首个数量替换规则。
3. 将产品描述完整替换为同一个德文标题。文本按纯文本转义为 HTML，避免把表格中的尖括号等内容当作可执行标记。
4. 第一条 Bullet Point 写入同一个德文标题；扫描全部现有 Bullet Point，将其余条目全部清空。
5. 标题、描述和 Bullet Point 均回读核对；描述和 Bullet Point 在提交前再次检查及补齐。字段在重绘后重新查找，写入未保留时重试。
6. 下载结果仍为用户确认的 8 列，最终标题使用页面实际写入的德文标题。

## 字段定位与编辑器同步

- 产品描述：按用户提供的 data-path="product_description.0.value" 定位区域，再读取其中 textarea 的动态 ID，未写死 ckeditor14。
- 描述区域的 CKEditor 是 iframe 富文本编辑器，不能仅依赖隐藏 textarea 的显示值来确认最终内容。
- 使用独立 MAIN 世界脚本调用 CKEditor 公开 setData / getData / updateElement 接口，写入后触发 change 和表单事件，分别检查编辑器内容与隐藏表单值。
- 扩展隔离脚本与页面脚本通过只支持读写产品描述的固定消息通信；不增加浏览器权限，不访问私有框架状态、Cookie 或账号凭据。
- Bullet Point：按 textarea[id^="form_item_bulletPoints_"] 扫描，并按数字索引排序。
- 定位信息证据见 docs/evidence/german-content-fields.json。当前页面未通过浏览器工具直接读取，结构由用户粘贴提供；编辑器脚本使用店小秘公开的 4.6.2 版本。

## 验证

- 109 项 Node 回归通过，包括用户的 115 条数量标题、德国真实上传表、DE 别名、忽略数量、翻译必填和最终标题导出。
- 实际 CKEditor 4.6.2 的离线浏览器回归通过：编辑器正文、数据、隐藏 textarea 以及 change 事件接收的数据一致；6 条 Bullet Point 仅第一条有值。
- 已验证 DOM 节点替换后的重新定位、Chrome 隔离世界与 MAIN 世界通信、尖括号/HTML字符按文本保留、提交前回读，以及英国内容不被德国规则修改。
- 本地模拟认领与编辑验证 DE/德国、UK/英国双向等价；不同站点仍拒绝匹配。
- 未修改上传工作簿，未填写、保存或发布任何真实产品。

本地浏览器测试：tests/german-content-browser.cjs。实际编辑器资源缓存于 artifact-work/ckeditor-fixture，仅供测试，不随插件打包。首次准备资源可加 --prepare，正式验证仅使用缓存资源并阻止外部请求。
