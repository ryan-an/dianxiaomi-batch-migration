# 实现方案

标准 Chromium Manifest V3 扩展。依据真实 DOM 操作页面，不调用猜测的 HTTP 私有接口，不读取框架内存对象。

## 模块

| 文件 | 职责 |
|---|---|
| `core.js` | XLS/XLSX 数据标准化、用户授权的跨表合并、店铺别名、来源键、单位归一、结果表数据及 CSV |
| `popup.*` | 480px 浮动面板的共享 HTML/CSS/控制器：上传、开始、停止、进度、日志和结果下载 |
| `panel-view.js` | 从共享 HTML/CSS 生成的面板模板，由内容脚本在 Shadow DOM 内显示 |
| `panel-layout.js` | 拖动位置与视口边界计算 |
| `ui-model.js` | 状态与进度统计，兼容旧批次记录，供弹窗和页面浮层共用 |
| `work-target.js` | 优先绑定发起任务的网页面板所在标签页，排除其他来源 |
| `background.js` | 单批次互斥、唯一执行标签页、页面跳转、状态保存、提交意图标记、中断处理 |
| `workflow.js` | 分组采集、一次重试、标题映射、分页认领、移入、逐条编辑发布、结果核对 |
| `adapter.js` | 真实 DOM 选择、输入事件、Ant Select、VXE 行识别/分页/勾选、进度和校验读取 |
| `overlay.js` | 面板挂载、标题栏拖动、位置与收起状态保存、执行期间页面输入锁定 |

## 数据流

上传 → 表头识别与跨表补齐 → 自动匹配工作标签页，处理整张表 → 按实际店铺和站点分组 → 直接提交换行链接采集 → 等进度完成 → 查本批次失败项并重试一次 → 逐一对应来源/标题/采集ID → 当前页本批次批量认领 → 按来源/标题/店铺/国家找到采集箱产品ID → 当前页批量移入待发布 → 按标题搜索并核对ID、点击编辑 → 再次核对来源/标题/店铺/站点 → 逐字段填写（单字段失败记录警告并继续） → 等待2秒 → 检查并补填（失败记录警告） → 保存并发布 → 等待2秒 → 读取发布成功弹窗或平台校验 → 保存逐条结果 → 成功时关闭编辑标签、返回待发布列表处理下一条 → XLSX（长ID为文本）。

## 提交与恢复

可能改变服务器状态的命令执行前保存提交意图。填写和预检异常记录为警告，仍进入发布；发布前重新核对产品身份，错误产品不提交。点击发布后成功弹窗优先于残留字段错误，平台实际校验失败则记录本条失败后继续下一条。单条发布结果不明时保存 `publishUncertain` 标记，保留编辑页并继续下一条；恢复批次时跳过这些条目，不自动重复发布。批量移入状态不明或后台被浏览器终止时，仍保留提交意图与原有待核对规则。

分页按实际数据行而非分组行计数，VXE 固定列复制的行不作为额外产品。只选择本批次 ID，并在批量按钮点击前检查勾选结果。批量结果部分失败时，以后续实际列表中是否存在精确产品匹配来核对，不能将整个批次盲目视为成功。

容量按运行时可见的容量标签查找；如果出现独立单位字段，将如 `2oz` 的值拆为数字和单位，从实际下拉项中唯一匹配。字段有歧义时失败并保留原因。该分支尚未用另一真实类目消耗产品验证。
